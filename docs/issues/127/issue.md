## 概要

現在の`/issue`コマンドと`/branch`コマンドを統合し、issueの取得から開発ブランチの作成までを一つのコマンドで完結できるようにする。

## 現在の状況

- `/issue`コマンド: GitHubからissue情報を取得し、`docs/issues/{issue_number}/issue.md`に保存
- `/branch`コマンド: issue番号を基に開発ブランチを作成

## 提案する変更

`/issue`コマンドの責任範囲を拡大し、以下の機能を統合する：

### 統合後の`/issue`コマンドの動作

1. **Issue情報の取得** (既存機能)
   - GitHub CLIを使用してissue詳細を取得
   - `docs/issues/{issue_number}/issue.md`に保存

2. **ブランチ作成の自動化** (新機能)
   - Git作業ディレクトリの状態確認
   - 未コミット変更がある場合の対話的処理
   - 適切なブランチ名の生成と作成
   - 新ブランチへの切り替え

### パラメータ

- `issue_number` or `issue_url` (required): GitHub issue番号またはURL
- `branch_type` (optional): ブランチタイプ (feature/fix/hotfix、デフォルト: feature)
- `output_path` (optional): 出力ファイルパス

### 期待される効果

- 開発者の作業効率向上
- issue対応開始時の手順簡素化
- コマンド数の削減によるワークフローの改善
