# Pull Request #127: /branchコマンドを/issueコマンドに統合してissue対応準備の自動化を改善

## Description

このPRは、開発ワークフローの効率化を目的として、`/issue`コマンドと`/branch`コマンドを統合し、さらに開発プロセス全体を改善します。

**重要な追加修正**: PRコマンドでgit diffコマンドがページャーで止まってしまう問題も修正しました。

### 主な変更内容

#### 1. `/issue`コマンドの機能拡張
- **ブランチ作成の統合**: issue取得後に自動的にブランチを作成
- **デフォルト動作**: ブランチ作成がデフォルトで実行される
- **柔軟なパラメータ**: `branch_type`（feature/fix/hotfix）と`no_branch`オプション
- **後方互換性**: 既存の機能は完全に保持

#### 2. `/branch`コマンドの非推奨化
- **DEPRECATED**マークを追加
- **移行ガイダンス**: `/issue`コマンドの使用を推奨
- **レガシーサポート**: 必要に応じて既存機能を維持

#### 3. 開発ワークフローの改善
- **`/dev`コマンド**: コミット機能を削除、開発に専念
- **`/test`コマンド**: テスト実行とワークフロー内での位置を明確化
- **`/pr`コマンド**: コミット機能を追加、テスト後のコミット＋PR作成

### 新しいワークフロー

```bash
# 1. Issue取得 + ブランチ作成（統合）
/issue 127

# 2. 開発（コミットなし）
/dev 127

# 3. テスト実行
/test 127

# 4. コミット + PR作成
/pr 127
```

### 期待される効果

1. **効率向上**: コマンド数の削減（2コマンド → 1コマンド）
2. **品質保証**: テスト通過後のコミットを強制
3. **ワークフロー最適化**: 各コマンドの責任を明確化
4. **開発体験向上**: より直感的で効率的な開発プロセス
