## 概要

issueコマンドに自動ワークフロー機能を追加し、issue -> spec -> plan -> dev -> test -> pr まで一気に実行できるモードを実装する。また、既に統合済みで非推奨となったbranchコマンドを削除する。

## 背景

現在の開発ワークフローでは、各段階（spec、plan、dev、test、pr）を個別に実行する必要があり、開発効率に課題がある。一連の作業を自動化することで、開発速度の向上と作業の一貫性を確保したい。

## 要件

### 1. 自動ワークフロー機能の追加
- [ ] issueコマンドに `--auto` または `--workflow` パラメータを追加
- [ ] 以下の順序で自動実行する機能を実装：
  1. issue情報の取得保存
  2. ブランチ作成（既存機能）
  3. `/spec {issue_number}` の実行
  4. `/plan {issue_number}` の実行  
  5. `/dev {issue_number}` の実行
  6. `/test {issue_number}` の実行
  7. `/pr {issue_number}` の実行
- [ ] 各段階でエラーが発生した場合の適切なハンドリング
- [ ] 進行状況の表示とログ出力

### 2. 非推奨branchコマンドの削除
- [ ] `.cursor/commands/branch.md` ファイルの削除
- [ ] 関連ドキュメントからの参照削除
- [ ] issueコマンドに統合済みのため、機能的な影響なし

### 3. ユーザビリティの向上
- [ ] 自動ワークフロー実行時の進行状況表示
- [ ] 各段階での成功/失敗ステータスの明確な表示
- [ ] 中断再開機能の検討

## 実装方針

1. 既存のissueコマンドを拡張し、後方互換性を維持
2. 各コマンドの実行結果を適切にチェックし、エラー時は処理を停止
3. ログファイルによる実行履歴の記録
4. 非推奨ファイルのクリーンアップ
