# Issue #146 仕様書: ReCheckボタン実行後の自動ページ更新機能

## 概要
ReCheckボタンを押してチェックが完了した後、ページ内のアラートテーブルや関連情報を自動的に更新する機能を実装する。

## 機能要件

### 1. 自動更新対象
- **Active Alertsテーブル**: アクティブなアラートの一覧
- **Resolved Alertsテーブル**: 解決済みアラートの一覧
- **その他の関連情報**: ページ内のアラート関連の統計情報や表示データ

### 2. 更新タイミング
- ReCheckボタン押下後、チェック処理が完了した時点
- バックエンドからチェック完了の通知を受信した時点
- エラーが発生した場合も適切にエラー状態を反映

### 3. 更新方式
- **リアルタイム更新**: WebSocketまたはServer-Sent Eventsを使用
- **ポーリング方式**: 定期的にAPIを呼び出してデータを取得
- **ハイブリッド方式**: 初期はポーリング、接続可能時はリアルタイム更新

## 技術仕様

### フロントエンド
- **状態管理**: アラートデータの状態を適切に管理
- **UI更新**: テーブルコンポーネントの再レンダリング
- **ローディング状態**: チェック処理中の適切なローディング表示
- **エラーハンドリング**: チェック失敗時の適切なエラー表示

### バックエンド
- **通知機能**: チェック完了時のフロントエンドへの通知
- **API設計**: アラートデータ取得用のAPI
- **WebSocket**: リアルタイム通信のためのWebSocket接続

## 実装方針

### Phase 1: 基本的な自動更新機能
1. ReCheckボタン押下時のローディング状態管理
2. チェック完了後のポーリングによるデータ更新
3. テーブルコンポーネントの再レンダリング

### Phase 2: リアルタイム更新機能
1. WebSocket接続の実装
2. サーバーからのリアルタイム通知
3. 接続状態の管理とフォールバック

### Phase 3: UX改善
1. 更新アニメーション
2. 更新通知の表示
3. エラー状態の改善

## 非機能要件
- **パフォーマンス**: 更新処理は1秒以内に完了
- **可用性**: ネットワークエラー時も適切にフォールバック
- **ユーザビリティ**: 更新中は適切なローディング表示

## テスト要件
- **単体テスト**: 各コンポーネントの更新機能
- **統合テスト**: ReCheckから更新までの一連の流れ
- **E2Eテスト**: ユーザー操作から更新完了までのテスト
